## Phase 0 shared combat systems (shipped)

Henry approved the defaults:
- Launch roster: sword, dagger, rapier, two-handed sword and two-handed axe.
- A roll cannot cancel a skill's post-motion delay.
- Animations use the hybrid approach.

He asked to work in a research, design, implement, test and review loop. Design: [[Phase 0 shared combat systems]].

What changed in the live place:
- **New `ReplicatedStorage.Combat.CombatRules`.** All the combat math is in one pure module: damage types, counter hits, guard stamina cost, armor windows, hit damage, the stun update and stagger immunity.
- **CombatConfig** gains DamageTypes, ArmorDamageTaken, StaggerImmunityTime and a PvP table.
- **Types** gains DamageType and Armor on attacks, and DamageType, CritMultiplier and GuardDamage on weapons.
- **ClassDefaults.Sword** sets Slash, crit 1.5 and guard damage 1.0. RollAttack and Riposte are Pierce.
- **DamageService** now uses CombatRules: counter hits, the armor provider, per-class crit, guard cost by damage type, and PvP flags.
- **PoiseService**: the longest stun wins, plus stagger immunity.
- **CombatService** adds GetArmor and passes the damage type and class stats with hits.
- **SparringKnightService** sets CombatState Attacking during swings, so hitting it mid-swing is a counter hit.
- **WeaponController** obeys the server's Flinch.
- **WeaponRegistry** requires HitStart < HitEnd <= CancelOpen.
- **New `ServerStorage.CombatDev.Tests`** holds 14 unit tests.
- **Docs.Combat and the README changelog** are updated.

Verified:
- All 14 unit tests pass.
- All 8 acceptance criteria pass, with the numbers in the Phase 0 note. For example, a live counter hit dealt 26.4 against 24.0, and a knight hit during an armored heavy did 9.9 with no flinch.
- The integration test caught a one-frame gap in stagger immunity, which is fixed.
- A reviewer agent read the diff. Five issues are fixed, and five design questions are flagged in the Phase 0 note.
- The repo matches the live place, 75 of 75.
